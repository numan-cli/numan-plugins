The repository is a single orchestration layer centered on `manifest.json` (schema `numan-plugin-build-manifest-v0`) which declares the active plugin build matrix — each entry pins both a human-facing `tag` and an immutable `source_commit`, plus per-plugin `exclude_targets`/`exclude_reason`, Nu version bounds, and verified versions. `.github/workflows/build.yml` reads this manifest to drive a multi-runner matrix (ubuntu-latest, macos-15-intel, macos-15, windows-latest) using Rust toolchains including `taiki-e/setup-cross-toolchain-action` for Linux aarch64. The Python scripts in `scripts/` are invoked sequentially by the workflow: `package_plugin.py` normalizes artifacts into deterministic `.tar.gz`/`.zip` archives, `gen_spec.py` produces `kind:binary` specs consumed by numan-registry, and `release_transaction.py` performs safe draft-release transactions. Trust is split across repos — this repo builds and hosts binaries only, never holds signing keys; `numan-registry` independently hashes every uploaded asset and signs the index with its Ed25519 trust root. Provenance flows bottom-up: upstream tag → verified commit → manifest entry → release asset → spec file → signed registry index.
